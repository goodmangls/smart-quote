🐛 war-risk 단위 불일치 수정 + 0 이 가리던 것을 드러내는 가드 추가 (FE 퍼센트 vs BE 분수, 100배) — **실제 버그였고, 바로 앞 커밋에서 내가 만든 rates 게이트가 이걸 놓쳤다.** FE 는 `intlBase * (WAR_RISK_SURCHARGE_RATE / 100)` 로 **퍼센트(0~100)** 로 읽고, BE 세 계산기는 `base * WAR_RISK_SURCHARGE_RATE` 로 **분수(0~1)** 로 읽고 있었다. 🔴**0 은 어떤 단위 체계에서도 0 이라 완전히 안 보였다** — 상수가 `0`(DEC-006 으로 제거됨)이었기 때문에 모든 테스트·공유 픽스처·새 스냅샷 게이트가 전부 초록인 채로 양쪽이 100배 어긋나 있었다. 누가 `2`(2% 의도)를 넣으면 화면은 2%, **저장 견적은 200%** 가 된다 — 고객에게 청구되는 쪽이 후자다. 어느 쪽이 맞는지는 추측하지 않고 관례로 확정했다: **BE 도 FSC 를 `fsc_percent / 100.0` 으로 쓴다**(`quote_calculator.rb:155`). 즉 퍼센트 상수는 0~100 이고 사용 시점에 나누는 게 이 저장소 방식이며 war-risk 의 BE 쪽만 빠져 있었다 — `ups_cost.rb`·`dhl_cost.rb`·`fedex_cost.rb` 각 1줄을 관례에 맞췄다. **오늘 동작은 불변**(0 이라 어느 해석이든 0). 🔒**값 비교 게이트로는 못 잡으므로 가드를 따로 만들었다** — 새 rates 게이트는 `0 == 0` 으로 통과한다. `war_risk_unit_spec.rb`(BE, `stub_const`)와 `warRiskUnit.test.ts`(FE, `vi.hoisted` + 부분 mock)가 상수를 **non-zero(2)로 주입해 `intlWarRisk / intlBase` 비율을 단언**한다. ⚠️2 를 고른 이유가 있다 — **0 과 100 은 어느 해석으로도 같은 답이 나와 아무것도 증명하지 못한다.** 두 파일은 서로를 주석으로 가리키고 같은 숫자를 고정한다: 한쪽만 있으면 "그 쪽이 자기 자신과 일관됨"만 증명된다. ⚠️`stub_const` 는 `around` 훅에서 못 쓴다(rspec-mocks 가 per-test 생명주기 밖을 거부) — `before` 로 바꿨다. **결함 주입으로 증명했다**: 수정을 되돌리니 **새 가드 3/4 RED**, 그런데 **기존 스위트는 전부 GREEN**(calculation_parity 77/0, snapshot parity 1/0). 기존 게이트가 초록이라는 사실 자체가 이 결함이 왜 안 보였는지의 증거다. ⚠️**작업 중 내 실수 하나** — 주입 스크립트가 중간에 `cd` 를 해서 trap 의 상대경로가 깨졌고 **복원이 실패해 세 파일이 되돌려진 채로 남았다.** 재적용 후 가드 GREEN 복귀와 `git diff --stat`(3파일 각 1줄)로 확인했다. 오늘 복원 로직으로 두 번 데였으니 다음부터 절대경로로 고정한다. 검증: tsc 0, eslint 0, vitest **1802/1802**(80파일), rubocop 159파일 0 offense, rspec **609/0**. ⚠️워킹트리에 환율 배너 오탐 수정(`fxDrift*`·`ExchangeRateWidget*`·로케일 4종)이 함께 있다 — 수출입은행 연동 대기로 보류 중인 별개 작업이니 경로 지정으로 분리해 커밋할 것.
