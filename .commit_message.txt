🔒 환율·FSC 상수를 스냅샷 드리프트 게이트에 편입 (미러인데 가드가 없던 유일한 쌍) — 코드 분석에서 나온 HIGH 항목이다. 요율표는 `tariffs.json` 스냅샷이 **전 셀**을 단언하고 계산 로직은 `calculation-parity.json` 공유 픽스처가 지키는데, **`rates.ts` ↔ `rates.rb` 만 저장소 안에 아무 장치가 없었다.** 유일한 검사가 `fx-apply.py --check` 인데 **저장소 밖 개인 스킬**이라 CI 가 돌리지 않고, 그 스킬이 없는 사람에겐 신호 자체가 없다. `DEFAULT_EXCHANGE_RATE` 는 고객이 보는 모든 USD 금액에 곱해지고 매주 바뀌며, `DEFAULT_FSC_PERCENT*` 는 DB 조회 실패 시 폴백이다 — 한쪽만 고치면 화면 견적과 저장 견적이 조용히 갈린다. `TariffSnapshot.build` 에 `rates` 섹션을 추가했다. 백엔드 스펙이 `build` 전체를 비교하므로 **BE 가드는 자동 확장**됐고 프론트 단언만 새로 썼다. 🔴**게이트가 붙자마자 내 가정 두 개를 깼다**: ①**`MAX_MARGIN_PERCENT` 는 파일명이 다른 곳에 미러돼 있었다** — BE 는 `rates.rb`, FE 는 **`business-rules.ts`**. 값은 둘 다 80 으로 우연히 맞아 있었을 뿐 강제 장치가 없었고, `rates.ts↔rates.rb` 만 비교하는 방식으로는 **영원히 안 보이는 드리프트**다. ②**`MAX_RULE_MARGIN_PERCENT` 는 백엔드 전용**이었다(`margin_rule.rb` 검증 상한, FE 대응물 없음) — 미러가 없는 값을 패리티 게이트에 넣으면 쓰지도 않을 상수를 번들에 억지로 만들게 되므로 제외하고 이유를 주석에 남겼다. **결함 주입 3방향으로 판별력을 증명했다**(통과만 봐서는 아무것도 검사하지 않는 테스트와 구분되지 않는다): 프론트 환율 1300→1301 → FE RED · 백엔드 FSC 46.75→47.75 → BE RED · 마진 상한 80→70(파일명 다른 그 쌍) → FE RED. **완전성 가드**도 넣었다 — 스냅샷에 상수를 추가하고 FE 단언을 빠뜨리면 키 목록이 어긋나 RED 가 된다. 이게 없으면 "게이트에 넣었는데 실제론 검사 안 되는" 상태가 조용히 생긴다. ⚠️**Codex 지적으로 실패 안내를 고쳤다** — 스펙 실패 메시지와 두 파일의 헤더 주석, rake `desc` 가 모두 `*_tariff` 만 가리키고 있어서, `rates.rb` 를 고쳐 실패한 사람을 **엉뚱한 파일로 보냈다.** 이제 두 출처 쌍을 다 명시하고 `MAX_MARGIN_PERCENT` 가 `business-rules.ts` 에 있다는 것까지 안내한다. ⚠️**작업 중 내 실수 하나** — 첫 결함 주입 스크립트가 복원에 `git checkout` 을 써서 **아직 커밋 안 된 `tariff_snapshot.rb` 의 rates 추가분을 HEAD 로 되돌려 지웠다.** 재적용했고 두 번째 스크립트는 바이트 복사본 복원으로 바꿨다. 검증: tsc 0, eslint 0, rubocop 158파일 0 offense, rspec **605/0**, tariffParity FE **5/5** · BE **1/1**. ⚠️전체 vitest 에서 6건이 떴으나 tariffParity 는 아니고, 매 실행마다 파일이 바뀌는 **부하 타임아웃 계열**이다(오늘 반복 확인). ⚠️**워킹트리에 환율 배너 오탐 수정(`fxDrift*`·`ExchangeRateWidget*`·로케일 4종)이 함께 들어 있다** — 수출입은행 연동 대기로 보류 중인 별개 작업이고 파일이 겹치지 않으므로 경로 지정으로 따로 커밋할 것. 그때 이 메시지를 그쪽 내용으로 다시 쓸 것.
